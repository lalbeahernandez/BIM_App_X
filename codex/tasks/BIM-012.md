# BIM-012 — Normalización de unidades

**Prioridad:** MUST  
**Objetivo de release:** MVP  
**Estimación orientativa:** 0.5-1.5 d  
**Dependencias:** BIM-006, BIM-010

## Objetivo

Resolver unidades de proyecto y representar SI/canonical + original cuando sea necesario.

## Prompt listo para Codex

```text
TASK: BIM-012 — Normalización de unidades

Objetivo:
Resolver unidades de proyecto y representar SI/canonical + original cuando sea necesario.

Antes de modificar código:
1. Lee completamente `AGENTS.md`.
2. Lee `README.md`, `docs/ARCHITECTURE.md` y `docs/DOMAIN_MODEL.md`.
3. Lee `specs/features/model-ingestion.md`.
4. Inspecciona el código y tests relacionados; no asumas que el harness sigue exactamente como fue generado.
5. Verifica las APIs de librerías antes de usarlas. No inventes métodos, imports ni contratos.
6. Revisa las dependencias de esta tarea: BIM-006, BIM-010.

Alcance:
- Implementa únicamente lo necesario para conseguir el objetivo de BIM-012.
- Mantén los boundaries actuales: domain/core no depende de vendors; BIM pesado se ejecuta async; tenant isolation se valida en servidor.
- Conserva identidad BIM mediante `(revision_id, GlobalId)` y `element_lineage` cuando aplique.
- Mantén histórico/provenance; no reemplaces datos históricos por un único estado mutable.
- Todo write crítico debe respetar audit/outbox cuando corresponda.
- Si necesitas cambiar un boundary, contrato público o decisión arquitectónica, crea/actualiza un ADR.

Criterios de aceptación:
- Conversión es determinista y testeada
- Unidad original se conserva
- Unidades incompatibles fallan explícitamente

Pruebas mínimas exigidas:
- unit conversion property tests

Restricciones:
- No hagas refactors masivos no relacionados.
- No elimines ni relajes tests para obtener verde.
- No añadas una dependencia sin justificar por qué la librería estándar o un adapter existente no basta.
- No cambies schema/contratos sin migration/versioning y tests correspondientes.
- No introduzcas secretos ni datos reales en fixtures.
- Distingue claramente implementación funcional de STUB/TODO(PROD).

Validación obligatoria antes de entregar:
python scripts/verify_harness.py
make lint
make typecheck
make test
make smoke

Ejecuta además los tests específicos que hayas creado/modificado.
Si algún comando no puede ejecutarse, documenta exactamente el bloqueo y no afirmes que pasó.

Entrega final de la tarea:
1. Resumen de comportamiento implementado.
2. Lista de archivos modificados/creados.
3. Migrations/contratos/eventos modificados.
4. Tests añadidos y resultado real de los comandos.
5. Riesgos, deuda o TODO(PROD) restantes.
6. Confirmación explícita de cada criterio de aceptación: PASS/FAIL con evidencia.
```
